fix(audit): independent second-opinion review で見つかった脆弱性 9 件を修正

依存更新:
- filippo.io/age v1.2.0 → v1.3.1 (GO-2024-3344)
- golang.org/x/crypto v0.41.0 → v0.51.0 (GO-2025-4116/4134/4135)
- govulncheck: 0 vulnerabilities

CRITICAL:
- C1: /reply に CSRF が無かった → anon CSRF cookie (Path=/reply) を追加、POST で検証
- C2: AddOnionExistingKey が privKey/targetHostPort を素直に文字列連結していたため、
  ingress.key 改竄経由で Tor control 任意コマンド注入が可能だった
  → ED25519-V3: prefix 強制、\r/\n/\0 と空白文字を reject
- C3: viewer の tar 展開で symlink/hardlink を黙ってスキップ + Windows ドライブ文字や
  UNC パスを十分にチェックしていなかった
  → safeTarName() でドライブ文字/UNC/絶対パス/.. セグメント/制御バイトを reject
  → tar.TypeSymlink/TypeLink を明示的に拒否、未知 Typeflag も拒否
  → filepath.Abs(dir) + HasPrefix check で再確認

HIGH:
- H1: ParseMultipartForm が >32 MiB の添付を /tmp に書き出していたが
  RemoveAll が呼ばれていなかった → 平文添付が disk に残留 (SPEC F-X6 違反)
  → defer r.MultipartForm.RemoveAll() を追加
- H2: /reply の has-reply / no-reply 分岐が wall-time に観測可能
  → deadline を 1500ms → 2500ms に延ばし、no-match と no-reply の両パスで dummy HKDF + DecryptSymmetric を実行
- H3: /admin/login に CSRF なし → 同じく anon CSRF cookie (Path=/admin/login) で防御
- H4: Tor password の改行注入を防ぐため AUTHENTICATE 送信前に hasControlBytes() で reject
- H5: Duress TOTP が admin password の正解を要求していなかった
  → 攻撃者が duress TOTP を ~1/10^6 で当てて全 wipe させられた
  → 「正しい admin password + duress TOTP」の AND 条件に修正
  (password 不正だと duress 判定はスキップ → 通常の認証失敗として扱う)

MEDIUM:
- M7: LoadSecrets / SaveSecrets で平文 JSON body を defer zero に追加

LOW:
- L4: PaddedWriter.Flush で pad が 14 バイト未満 (HTML コメント wrapper の最小長) の時に
  strings.Repeat に負数が渡って panic していた
  → neededPad() で pad < 14 なら blockSize 分だけ overshoot

検証済:
✓ /submit POST → CSRF + PoW 両方 → 通常通り成功
✓ /reply POST without CSRF → 403
✓ /reply POST with CSRF → 2.5s 固定 wait
✓ /admin/login POST without CSRF → 403
✓ Duress with WRONG password → 認証失敗、case 数変わらず
✓ Duress with CORRECT password → 認証失敗を装いつつ case 全 wipe
✓ Tor private key with \r\n 注入 → reject
✓ Tor private key without ED25519-V3: prefix → reject
✓ build / vet / gofmt / govulncheck 全て clean
